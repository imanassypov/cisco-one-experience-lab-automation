# 2026-09-22

- **Bootstrap — the IOS-XE web root is no longer root-owned.**
  `/var/www/iosxe-images` was created `root:root 0755`, so a student who tried
  to `scp` a `.bin` straight into it got `Permission denied` and had no way
  forward except `sudo`. It is now owned by the login user
  (`script_server_image_owner`, defaulting to `ansible_user_id`, so it follows
  whoever runs the bootstrap rather than hardcoding `cisco`), and published
  images are written with that owner instead of `root`. A directory handover
  alone would not have been enough: `scp` truncates an existing file in place,
  which needs write permission on the *file*, so a new task also hands over any
  `.bin` left root-owned by an earlier run. nginx is unaffected — it reads as
  `www-data` and `0755`/`0644` still serve. Staging via the checkout plus
  `--tags image_server` keeps working exactly as before; copying into the web
  root is now simply also allowed. On a box bootstrapped before today, re-run
  `01_bootstrap_script_server.yml --tags image_server` once to take ownership.

- **Bootstrap — Python pins now have one source of truth.** `ansible-core`,
  `paramiko`, `netaddr`, both CatC SDKs and `rich` were pinned twice: once in
  `ansible-automation/requirements.txt` for `stage-script-server.sh`, and again
  as `script_server_*_version` variables feeding
  `script_server_python_packages` in the bootstrap role. The two agreed, but
  bumping one and forgetting the other would have had the role silently
  reinstall a different version over the staged one — and the evidence block
  would still have looked clean. `venv.yml` now installs from
  `requirements.txt` directly (`ansible.builtin.pip: requirements:`) and then
  adds Genie/pyATS as a second, separate task.
  `script_server_python_packages` is now just those two. Genie and pyATS stay
  out of `requirements.txt` on purpose: roughly 700 MB that is not needed to
  run `ansible-playbook`, so staging stays fast and only the bootstrap pays
  for it. A missing `requirements.txt` now fails the play with an explicit
  message instead of building an unpinned venv. Bump a shared version in
  `requirements.txt` and both paths follow.

- **Bootstrap — the end of `01` now tells you to reload your shell.** Students
  finished a clean bootstrap, read `PATH binaries: [...]` in the evidence
  block, then hit `Command 'ansible-playbook' not found` in the very same
  shell and assumed the run had failed. Nothing had: `01` appends the venv
  export to `~/.zshrc`, `~/.bashrc`, `~/.profile` and `~/.zprofile`, and a
  shell that is already open never re-reads those files. The evidence line was
  actively misleading because the check exports `PATH` inside its own task
  before calling `command -v`, so it only ever proved the binaries exist. It
  now reads "PATH binaries (resolved with the new PATH applied)" and is
  followed by an explicit **NEXT** line: run `exec $SHELL -l` or open a new SSH
  session, then `ansible-playbook --version`. The same correction is in the
  root README, the collection 00 README and the closing message of
  `stage-script-server.sh`, all of which previously said only "a new shell".

- **Bootstrap — `00_scriptserver_bootstrap/setup-local-venv.sh` removed.** The
  script had been a tombstone since 2026-09-16: its whole body printed "this
  built a venv on the student laptop, which is no longer part of the lab flow"
  and exited 1. Nothing in the repository referenced it — not the root README,
  not the collection 00 README, not the User Guide, not the pipeline subway
  map — and the campus README file tree already listed
  `stage-script-server.sh` as the script to run first. The laptop venv is gone
  for good: collection 00 runs **on** the script server over
  `ansible_connection: local`, so the supported path is SSH to
  `198.18.134.12`, clone the repository there, then `./stage-script-server.sh`
  followed by `00_preflight.yml` and `01_bootstrap_script_server.yml`. Anyone
  running the old command from muscle memory now gets "no such file or
  directory" instead of the pointer; a `git pull` brings the current README
  with it.
