# 2026-09-24

- **Docs — the guide now tells students to reload their shell after the
  bootstrap.** Step 4 of card 1 had the two bootstrap commands with their full
  `~/venv/bin/` path, and a 🛑 callout warning not to let apt install
  `ansible-core` — but it never said what to do instead, and every command from
  Step 5 onward silently switches to a bare `ansible-playbook`. The missing
  piece was the reload: `01_bootstrap_script_server.yml` puts `~/venv/bin` on
  `PATH` by writing to the shell startup files, and a shell that is already open
  never re-reads them, so `ansible-playbook` stays "command not found" in that
  session. A clean, successful bootstrap therefore looks broken.

  This exact failure was fixed on 2026-09-22 in the root README, the collection
  00 README and the closing message of `stage-script-server.sh`. The student
  guide was not on that list and kept the gap.

  Step 4 now carries an explicit reload step — `exec $SHELL -l` then
  `ansible-playbook --version`, or open a new SSH session — states that the
  bootstrap worked and the shell has simply not caught up, and says the
  `~/venv/bin/` prefix can be dropped from there on, which is what the rest of
  the guide assumes. The apt warning now points at the reload instead of only
  forbidding the wrong fix.

  Checked by sweeping every `ansible-playbook` invocation in the whole file
  rather than reading the one card: the only full-path uses are the two
  bootstrap commands in Step 4, and the venv-repair callout in card 3 where the
  explicit path is the point. All 30 others are bare, consistent with the new
  instruction.

- **Docs — the guide now explains where the IOS-XE images go, and where those
  paths are defined.** Staging the SWIM images was documented in the campus
  README but appeared **nowhere** in the student guide: no mention of
  `iosxe_images/`, `image_base_url`, or port `8080`. A student following only
  the guide would reach stage 09 with nothing to install, and would find out
  part-way through a pipeline run, after the fabric was already built.

  New **Step 5 — Stage the IOS-XE software images** in card 1, between the
  bootstrap and moving to the pipeline directory. It covers the `scp` onto the
  script server, the exact folder and filenames, publishing with
  `--tags image_server`, and a `curl -sI` that proves Catalyst Center will be
  able to fetch the file.

  It also answers the question the README only implies — *where is this path
  actually set?* — with a table mapping each setting to the file that defines
  it: `script_server_image_source_dir`, `script_server_image_root` and
  `script_server_image_http_port` in the bootstrap role's `defaults/main.yml`,
  `swim.image_base_url` / `image_file` / `rollback_image_file` in
  `settings.json`, and the line in `roles/swim/tasks/import_and_tag.yml` that
  joins the last two into a download URL. Three separate settings have to agree,
  and a typo in any of them produces the same "could not import" symptom, so the
  guide says which check isolates which half.

  Card 1's later steps renumbered 5–7 → 6–8, and the three cross-references that
  named them updated. Every value in the new step was verified against the repo
  rather than copied from prose.

- **Docs — `iosxe_images/` now has the README its own `.gitignore` expected.**
  The ignore rules carried `!iosxe_images/README.md`, un-ignoring a file that
  had never been written, so anyone opening the folder found only a `.gitkeep`
  and no indication of what belongs there — on the one folder in the repository
  whose contents a student has to supply by hand.

  It now explains what to drop in, why the `.bin` files are not in git, and
  traces the path end to end: `iosxe_images/` → the bootstrap's
  `http_image_server` tasks → `/var/www/iosxe-images` → nginx on 8080 →
  Catalyst Center. It carries the same settings table as the guide, so the three
  places that have to agree are listed with the file defining each, plus the
  `import_and_tag.yml` line that joins `image_base_url` and `image_file` into a
  URL. Also covered: why images are served locally rather than from cisco.com
  (`NCSW10375`, and `software.cisco.com` answering 403 from inside the pod), and
  a troubleshooting table that separates a filename mistake from a publish
  failure from nginx being down. Every value checked against the repository.
