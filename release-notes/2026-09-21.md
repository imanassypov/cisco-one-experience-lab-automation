# 2026-09-21

- **Docs — `GETTING_STARTED.md` merged into the campus EVPN README and
  removed.** Two entry-point documents meant a student had to guess which one
  to open, and setup facts drifted between them. The README now opens with a
  contents table, then **Before you begin** (steps 1–7: VPN, clone, `.vault`,
  bootstrap, `PATH`, POD number, inventory check), then **Pipeline order**, then
  the existing per-stage reference. Setup troubleshooting is merged into the
  one troubleshooting section, and the file tree is kept as a reference
  appendix. Any bookmark to `GETTING_STARTED.md` should become
  `README.md#before-you-begin`.
- **Docs — access points now have their own Stage 11 section.** The AP
  procedure was buried inside Stage 10 under a heading that did not name a
  stage, so there was no Stage 11 to navigate to. It now says up front that
  `11_await_access_points.yml` does the whole job, with the manual procedure
  kept below as explanation and fallback.
- **Docs — the orchestrator description was wrong.** It claimed
  `00_site_deploy.yml` runs stages 01–09 and excludes 10. It runs **01–10** and
  excludes 11 and 12, and because stage 09 is included a plain run reloads the
  fabric. The `-e swim_activate=false` caveat is now stated with it.
- **Docs — root README now onboards a first-time student.** It stopped after the
  bootstrap commands and never said what to run next. It now covers the setup
  that is common to every collection — connect and clone, stage and bootstrap,
  set `lab_pod_id`, the working-directory rule, where credentials live — then a
  **Next steps** table pointing at each collection's own guide, campus EVPN
  first and Splunk assurance second. Collection-specific detail stays in the
  collection docs.
- **Docs — SWIM is now documented as optional, with its image prerequisite up
  front.** Stage 09 does nothing until the `.bin` files are staged into
  `iosxe_images/` and republished with
  `01_bootstrap_script_server.yml --tags image_server`. That requirement was
  only discoverable by reading role comments.
- **Docs — corrected stale SWIM documentation in the campus README.** It still
  described CCO import as the only source, but `settings.json` has used
  `import_source: remote` since 2026-09-19 because this pod refuses CCO images
  with NCSW10375. Phase numbers and evidence filenames also still said `11.x` /
  `11_swim-*` from before the renumber; they are `09.x` / `09_swim-*`.
- **Docs — campus README stage list was missing SWIM.** The summary list at the
  top skipped stage 09, which pushed every later entry one number out, and it
  claimed stage 12 SSHes to the switches. Stage 12 reads CLI through Catalyst
  Center Command Runner; no stage SSHes to a device.
- **Docs — visual map of `settings.json`.** `Settings/README.md` now opens with a
  one-page diagram of the whole file, so an operator can find the block they
  need without scrolling 600 lines. The map also marks which pipeline stage
  reads each block, and flags that `{POD}` / `{APn_MAC}` are runtime tokens
  resolved from the per-student `lab.yml` — never values to paste in by hand.
- **Docs — stage numbers corrected.** Several references still pointed at the
  pre-renumber SWIM stage. Following them ran the wrong playbook.
- **Lint — campus collection is `ansible-lint` clean.** No behaviour change;
  it makes future lint failures signal rather than noise.
- **Process — added this `release-notes/` folder.** Behaviour changes are now
  expected to land with a dated note.
