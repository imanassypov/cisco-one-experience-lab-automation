# 2026-10-16

- **settings — rename `managed_ap_locations` to `primary_managed_ap_locations`.**
  Catalyst Center renamed the parameter at 2.3.7.6 to distinguish primary from
  secondary managed AP locations, and Cisco's own provision workflow examples
  use the new name for 3.1.x appliances. `settings.json` and the wireless pass
  now use it. The old key still works: the role reads the new name first and
  falls back to the old one, so an existing customised `settings.json` keeps
  running. A `secondary_managed_ap_locations` list is now also passed through to
  the workflow manager when declared, so it is not cleared on provisioning.

- **provisioning — assign the wireless controller's managed AP locations before
  provisioning it.** Stage 08 could fail with `NCWS70003 "Managed AP Locations
  are not configured for the device"`. `provision_workflow_manager` assigns the
  locations and calls the provision API about half a second later, before
  Catalyst Center's provisioning check can see the result, so the provision was
  refused even though the assignment had succeeded. The wireless pass now
  resolves each `primary_managed_ap_locations` path to a site ID, assigns the locations
  itself, and waits for Catalyst Center to report the expected count before
  handing over to the workflow manager. Tunable with
  `wlc_ap_location_confirm_retries` and `wlc_ap_location_confirm_delay` in
  `connection.yml`. A path that does not exist in the hierarchy now fails
  naming the missing site instead of producing the same opaque error.

- **verification — stage 12 now reports a mismatch instead of failing the run.**
  `verify_fail_on_mismatch` defaults to `false`. The stage collected every
  command and wrote both reports, so the run has done its job; a mismatch is a
  finding to read, not a red task at the end of a successful deployment. The
  verdict is printed as the stage's last line and is already stated in both the
  Markdown (`PASSED`/`FAILED`) and HTML (`Conformant`/`Non-conformant`)
  reports. Add `-e verify_fail_on_mismatch=true` for a pipeline that gates on
  the exit code.

- **verification — stop stage 12 aborting when no access point has joined yet.**
  `show ap tag summary` on a controller with no access points still prints
  `Number of APs: 0` and the column headers, so Genie parses that much and then
  raises `SchemaMissingKeyError` rather than the empty-parser error the filter
  recognised. The whole run stopped instead of recording a failed check.
  `genie_parse` now treats both signals as "the device has nothing to report"
  and returns an empty result, so the access point checks fail on their own
  terms and the report is still written. A genuine parsing problem, such as a
  missing parser, still aborts the run.

- **docs — correct the Stage 08 call order.** The student guide's Stage 08 flow
  now shows the managed AP location assignment and confirmation as their own
  step ahead of the controller provision, instead of implying the workflow
  manager does both.

- **docs — fix the link to the sample DC verification report.** The Stage 08
  fabric verification card pointed at a filename that does not exist; it now
  resolves to `verfication/dc-stage08-verification-sample.html`.
