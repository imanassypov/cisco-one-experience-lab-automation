# 2026-09-19

- **SWIM — moved to stage 09, ahead of the composite deploy.** The image upgrade
  now happens before the EVPN push, so the fabric is already on its intended
  image when configuration lands. Intent verification moved to stage 12, and the
  role was renamed to `swim`. Existing `--tags` and stage numbers from before
  this date no longer match.
- **SWIM — switched to `cisco.catalystcenter`.** `cisco.dnac` crashes during
  golden-image tagging on this Catalyst Center version.
- **SWIM — idempotent on an already-upgraded fabric.** Re-running stage 09 on
  devices already at the target image is now a no-op instead of a false failure,
  and it no longer crashes on devices whose API response omits the
  `goldenImages` key entirely (Catalyst Center omits it rather than nulling it
  for untagged devices).
- **SWIM — images served from the script server.** IOS-XE binaries are published
  over HTTP from the bootstrap host and pulled by Catalyst Center, replacing the
  CCO import path that reported success without importing anything. Upgrade and
  rollback images are imported separately.
- **Telemetry — dropped the unsupported EVPN route-statistics block.** The
  templates pushed a statistics subscription the platform rejects; subscription
  40113 is now disabled. Devices stop logging the rejection on every push.
- **Assurance — Splunk lookups keyed on the short hostname.** Fabric events were
  failing to join their device metadata when the FQDN was used.
- **Assurance — Splunk restarts are safer.** Dropped `-auth` from the restart
  call, and a restart that hits its timeout now recovers the service instead of
  leaving Splunk stopped. Dashboard validation also no longer fails on a token
  the validator cannot bind.
