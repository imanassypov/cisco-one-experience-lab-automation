# 2026-11-13

- **repo — the student guide moved to its own repository.** `docs/` (368 MB of
  HTML, screenshots and sample reports, and about 470 MB of its history) is now
  [cisco-one-experience-lab-guide](https://github.com/imanassypov/cisco-one-experience-lab-guide),
  published at https://imanassypov.github.io/cisco-one-experience-lab-guide/.
  Its git history came with it. Here, `docs/` holds only a redirect, so the old
  Pages URL, including `#section` links, still lands on the guide. Edit the
  guide in its own clone; do not add guide content back to this repository.
- **bootstrap — student clones are shallow.** Every clone command (guide,
  `stage-script-server.sh`, `00_preflight.yml`, the bootstrap and EVPN READMEs)
  is now `git clone --depth 1 --single-branch`. With the guide gone, that pulls
  only the current automation tree instead of every docs revision ever pushed.
  Initially, existing full clones could use `git pull` to remove the local
  `docs/` content, but still downloaded the old guide's history. The subsequent
  history purge below requires those clones to be replaced.
- **repo — historical guide content purged from the automation repository.**
  Removing the current guide files alone did not shrink ordinary clones:
  `main` still referenced about 450 MiB of historical guide blobs
  (uncompressed). The `docs/` history was removed from all published branches
  (`main`, `feature-assurance`, `master`) and `eval-nd-l3out-base`, and the tiny
  Pages redirect was restored on `main`. The separate guide repository and its
  history are unchanged. Full clones no longer need the old guide assets.

  **Migration:** commit IDs changed. Keep your old checkout as a local backup
  and clone again into a new directory:

  ```bash
  git clone https://github.com/imanassypov/cisco-one-experience-lab-automation.git \
    cisco-one-experience-lab-automation-clean
  ```

  Copy any uncommitted work and gitignored configuration (including `.vault`,
  POD overrides, and locally staged software images) from the old checkout
  into the new one before using it. Review unpublished commits separately and
  port only their changes, not their old ancestry. Do not use `git pull` to
  merge the rewritten history or push old branches or tags back: that can
  reintroduce the deleted guide assets. Commit links using old IDs may no
  longer resolve.
